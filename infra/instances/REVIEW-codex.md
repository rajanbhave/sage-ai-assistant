## 2. Bugs and risks, highest impact first

1. **The video’s central attribution claim lacks a measured tenant-to-model result.** The JWT tenant claim is present on the incoming authenticated route, and the bearer is forwarded to the Gateway (`agent/agent.py:234–244`). Sage’s model client and call path supply neither a dedicated tenant header nor Bedrock `requestMetadata`. The DoiT reference accepts an inbound `x-tenant-id` and stamps `requestMetadata` on both Converse operations. Sage’s one-provider/one-workload mapping can support a tenant rollup if capture and the mapping are demonstrated. It does not establish that Attribute extracted an identifier from individual requests. **Fix:** First inspect one common UTC interval in Attribute for workload, model, input/output tokens and the resolved tenant for **both** lanes. If workloads appear without tenants, configure and verify an identifier derived from the trusted lane or verified claim. Where supported by the receiver, add the non-secret lane value to both Converse and ConverseStream metadata. Keep JWTs out of model metadata. If workloads lack model usage altogether, have the sensor operator check effective TLS targeting, event-stream decoding and export receipts for these two hosts before generating more volume. Bedrock model invocation logging was unconfigured in this region. Adding request metadata alone does not create billing line items. [Reference agent, lines 301–320](https://github.com/doitintl/attribute-agent-core/blob/440353465e030064d663863f27dd7ca7127fecc2/agent-3d-render/agent.py#L301-L320) · [DoiT tenant attribution example](https://www.doit.com/blog/blog-bedrock-agentcore-per-tenant-cost-attribution) · [AWS per-request metadata](https://docs.aws.amazon.com/bedrock/latest/userguide/cost-mgmt-request-metadata.html)
2. **The live deployment ZIP expires before the talk.** `HeadObject` for `sage_agent_inst/deployment.zip` returned `expiry-date="Tue, 01 Dec 2026 00:00:00 GMT"`. The rule covers the whole bucket, including the rebuilt artifact. Both lanes use that key, and `deploy_instances.py:95–123` overwrites it. An existing warm agent can mask a missing artifact. Redeployment or a launch that needs to fetch the ZIP is exposed. **Fix:** Keep an immutable, digest-named copy under retention through teardown, update both runtimes to that artifact, and verify a fresh launch before 3 December. Repackaging into the same expiring key only resets the clock.
3. **The traffic generator counts HTTP successes even when the agent streams a failure.** `traffic.py:55–67` discards the body on HTTP 200. `agent/agent.py:313–320,336–347` can emit an identity or request error inside a successful stream, including failures before the model runs. The generator also records the first 300 characters of other error bodies. **Fix:** Count completed streams with a terminal model result, count in-stream failures separately and log only allowlisted status/error codes. At `traffic.py:75–80` calls are serial and the random wait starts after the response. The 3:1 weighting applies to attempted prompts, while 40/hour is the mean pacing before service time. Tool loops and response lengths change token and dollar ratios. The 48-hour run started on 23 November and is scheduled to finish on 25 November. For the recording, warm each lane and check recent completed calls. The shared session ID can outlive the EC2 host’s 900-second idle and 28,800-second maximum lifetime.
4. **The browser header works, but the runbook omits a recording prerequisite and overloads the login session ID.** For origin `http://localhost:5173`, both runtime URLs returned `Access-Control-Allow-Origin: *`, allowed `POST`, and explicitly allowed `authorization,content-type,x-amzn-bedrock-agentcore-runtime-session-id,x-sage-correlation-id`. The probe’s shorter header list also passed. The session header controls service routing. The live forwarding allowlist of `Authorization` and `X-Sage-Correlation-Id` controls what reaches agent code. Adding the reserved session header there is unnecessary. The probe deliberately omits the session header and only counts an observable 401/403 (`frontend/src/lib/demo/cross-lane-probe.ts:33–62`). **Fix:** Specify `VITE_DEMO_STAGE=true`, both Instances URLs, session IDs and current evidence log groups when building the kiosk (`frontend/src/lib/demo/config.ts:12–18`, `README.md:66–79`). Rehearse same-lane success immediately followed by the other-lane denial with the same signed-in user. Keep a unique local login ID and a separate wire-level runtime session ID. The pinned value currently also keys React panels and the stale termination guard (`frontend/src/lib/auth/cognito.ts:89–94,234`, `frontend/src/App.tsx:53–65,94–99`). A later login in the same lane reuses it. Gate shared pins to a single-user-per-lane demo. Instances do not enforce per-user ownership of a session ID. [AWS custom-header handling](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-header-allowlist.html) · [AWS session isolation](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-sessions.html)
5. **Teardown can race provider-owned network interfaces and leave demo resources behind.** `README.md:93–105` waits for runtimes, then requests provider and stack deletions back-to-back. Both providers currently reference runtime versions 1 and 2. **Fix for 4 December:** End demo traffic and restore the previous frontend endpoints, session settings and log groups. Remove the demo runtimes, verify no versions reference either provider, delete the providers, then wait for their disappearance and their managed instances/interfaces to clear. Provider deletion includes its sessions. Delete the stack, wait for completion, and check the NAT gateway, EIP and VPC. Explicitly retain or dispose of the two Instances runtime log groups, the installer Lambda log group and any retained ZIP. All three log groups currently lack a retention limit. Treat the seven-day secret deletion as scheduled recovery. Reconcile demo users and scope grants with their owner before removing anything from the shared identity stack. [AWS Instances deletion semantics](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/runtime-instances-data-management.html)
6. **A successful install is remembered even if the sensor later stops.** `sensor_installer.py:37–41,60–69` skips a host after historical SSM success. The host can then miss traffic for the rest of its life. The installer starts after EC2 launch and SSM registration, so early calls can also escape capture. Code and workload mappings are patched outside CloudFormation, whose template declares an inline stub and empty map (`stack.yaml:160–189`, `deploy_instances.py:217–224`). The declared handler and inline stub module also differ. **Fix:** Manage the real packaged handler and mapping as deployed configuration, verify them after stack changes, reconcile current service/export health, and make capture readiness precede the measured traffic window. Pin the sensor build used in the recording.
7. **Provisioning exposes more diagnostic data and authority than needed.** `deploy_instances.py:36–43,182–185` includes all copied environment values in dry-run output. `sensor_installer.py:29–33` hands the installation credential to a process as an argument and returns raw journal lines to SSM. The operator role has service-wide wildcards, and the installer role can send shell commands to all EC2 instance ARNs in the account/region (`stack.yaml:128–137,149–158`). **Fix:** Print allowlisted dry-run fields, use the approved runtime secret-injection mechanism, return structured health only, and scope instance-target permissions to the intended managed fleet where supported. Paginate the existing-provider/runtime lookups at `deploy_instances.py:172–174` and verify an existing resource’s configuration before reuse.
8. **Registry fallback can silently produce an incomplete skill set.** Both pinned runtime streams recorded “using bundled skills,” and both live host work directories contained the expected two SKILL.md files. That covers the observed registry-list failure. Individual record errors are swallowed before the outer fallback, an empty registry response bypasses it, and a missing registry ID aborts before it (`agent/agent.py:118–164`). The final log labels bundled skills as registry-loaded. **Fix:** Define the two skills required for this demo, verify their presence after loading, fail clearly or use the approved bundled set for recoverable errors, and log the actual source. Preserve any intentional registry approval or revocation policy.
